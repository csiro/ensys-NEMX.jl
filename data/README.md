# Data directory

Everything the models read, and everything the scripts write. Only the MATPOWER
network cases are committed; the rest is ignored by git and reproducible from
AEMO's public data. See the root `.gitignore` for exactly what is and is not
tracked.

## What is committed

| Path | Size | What it is |
|:-----|:-----|:-----------|
| `snem2000_fixed.m` | 1.4 MB | Synthetic 2000-bus NEM network case, AC only, with the NEM side tables (`gen_data`, `storage_data`) carrying participant DUIDs. Input to `NEMX.NBenchmark`. |
| `snem2000_acdc_fixed.m` | 1.4 MB | The same network with the HVDC links modelled as converters rather than DC lines. Input to `NEMX.OPFFCAS`. |
| `generator_mapping.yaml` | 1 KB | Overrides for participant-to-bus attachment where the automatic DUID match is wrong or ambiguous. |

A smaller six-bus fixture, `test/data/matpower/nem6_test.m`, is committed
separately and is what the test suite uses. It exists so the network layer can
be exercised in under a second.

## What is not committed, and why

| Path | Size | Why |
|:-----|:-----|:----|
| `nemx_<YYYY_MM>/historical_mms.db` | ~1.4 GB per month | SQLite mirror of AEMO's MMS data model. Rebuildable in minutes. |
| `nemx_<YYYY_MM>/xml_cache/` | 10–105 GB per month | One NEMDE case file per five-minute interval. September 2025 alone is 104 GB. |
| `nemx_<YYYY_MM>/*.csv` | ~200 MB | Model outputs — price sweeps, nodal results, event studies. Regenerated by the scripts that wrote them. |
| `figures/`, `results/` | varies | Script output. |

None of it belongs in a git repository: it is large, it is not ours, and it is
reproducible.

## Getting the data

### Download it

Every script that needs market data takes a `--download` flag, which fetches
whatever is missing and nothing that is not. Both downloads are idempotent —
a month already mirrored, or a day already cached, is skipped — so an
interrupted download resumes by re-running.

```bash
# One month of MMS tables plus the NEMDE case files for its days.
julia --project=. scripts/run_zonal_benchmark.jl random 10 --download \
      --year=2025 --month=9
```

Budget roughly 1.5 GB per day of NEMDE case files and a few hundred megabytes
for the MMS tables. A full month is a large download; if you only need a few
intervals, download the days you need rather than the month.

### Or point at an existing copy

Nothing requires the data to live here. Every script takes `--data-dir`:

```bash
julia --project=. scripts/run_network_day.jl \
      --data-dir=/mnt/bigdisk/nem/nemx_2025_09
```

If you already hold a copy elsewhere and want the default paths to work,
symlink it rather than duplicating it:

```bash
mkdir -p data/nemx_2025_09
ln -s /mnt/bigdisk/nem/nemx_2025_09/xml_cache        data/nemx_2025_09/xml_cache
ln -s /mnt/bigdisk/nem/nemx_2025_09/historical_mms.db data/nemx_2025_09/historical_mms.db
```

This working copy is set up that way: the CSVs are real files, while
`historical_mms.db` and `xml_cache/` are symlinks into the original
reference-implementation tree. `git status` stays quiet either way, because the
whole directory is ignored.

## Layout

```
data/
├── snem2000_fixed.m              committed
├── snem2000_acdc_fixed.m         committed
├── generator_mapping.yaml        committed
└── nemx_<YYYY_MM>/               ignored
    ├── historical_mms.db         MMS mirror (file or symlink)
    ├── xml_cache/                NEMDE case files (dir or symlink)
    └── *.csv                     model output
```

`nemx_<YYYY_MM>` is simply the directory name the scripts default to for a
given month of data; `--data-dir` overrides it.

## Provenance

All market data comes from AEMO's public NEMWeb portal:

- **MMS data model** — `https://www.nemweb.com.au/Data_Archive/Wholesale_Electricity/MMSDM/`
- **NEMDE case files** — `https://www.nemweb.com.au/Data_Archive/Wholesale_Electricity/NEMDE/`

The synthetic 2000-bus network is not AEMO data. It is a public synthetic case
for the NEM; it approximates the real network's structure and is not a model of
the actual transmission system. Results computed on it are properties of that
model, not measurements of the NEM.
